# SplitScreen Hub

Homebrew-каталог игр Nintendo Switch с мультиплеером **на одном экране**.
Отвечает на вопрос «нас четверо, во что поиграть»: фильтр «от N игроков»,
отметка того, что уже установлено на консоли, избранное и свои папки.

Приложение — C++17 поверх [borealis](https://github.com/xfangfang/borealis)
(devkitPro), данные собираются набором Python-скриптов из публичных API
nintendo.com. Лицензия MIT.

В каталоге **3489 игр**, из них 3015 показываются сразу — 474 переиздания
аркадных автоматов (ACA NEOGEO, Arcade Archives, SEGA AGES) скрыты и включаются
отдельным фильтром. У каждой известно точное число игроков на одной
консоли — не «мультиплеер есть», а «1–4».

## Откуда данные

Два публичных API, которыми пользуется сам nintendo.com:

**Algolia** (`store_game_en_us`) — каталог eShop. Ключевой фасет
`waysToPlayLabels: "Play together on one console"`.

**graph.nintendo.com** — карточка товара. Обязателен заголовок
`apollographql-client-name: ncom`, иначе сервер отвечает `Internal server error`.
Аргумент — OneOf-тип `ProductInput`, ровно один ключ: `sku` | `nsuid` | `urlKey`
(по `nsuid` доступно заметно больше товаров, чем по `sku`).

Главное поле — `numberOfPlayers`, и в нём три разных счётчика:

| Поле | Что значит |
|---|---|
| `.system` | **игроков на одной консоли** — то, что нужно |
| `.local` | локальный беспроводной на нескольких консолях |
| `.online` | онлайн |

У Mario Kart World это `system 1–4`, `local 2–8`, `online 2–24`. Европейский API
(`searching.nintendo-europe.com`) для этой задачи не годится: там единственное
поле `players_to` даёт суммарное число — у Fortnite 100, у Terraria 8 при
сплитскрине на двоих.

Около половины каталога GraphQL анонимно не отдаёт (`UNAUTHORIZED`), причём это
не связано ни с доступностью игры, ни с ценой. Такие карточки берутся со
страницы товара: она открывается обычным GET с полными браузерными заголовками
(без них 406), а в её `__NEXT_DATA__` лежит тот же объект `Product`.

## Что не попало в каталог

- **223 бандла-сборника** (nsuid `7007*`) — у них нет ни числа игроков, ни
  Title ID, ни размера
- **будущие релизы**
- **32 игры**, по которым не нашлось надёжного подтверждения мультиплеера
- **3 игры с неверной меткой eShop**: у HELLCARD кооператив только по сети,
  Double Kick Heroes одиночная, а LEGO Voyagers Friend's Pass вообще не игра,
  а пропуск для приглашения по сети

Ещё 48 игр eShop пометил `Single player`, хотя мультиплеер у них есть — среди них
все 14 Jackbox Party Pack, Rocket League, Stardew Valley и Terraria. Их числа
проверены вручную и лежат в `make_overrides.py` вместе с источником по каждой.
Там же видно, почему проверять надо именно версию для Switch: у Stardew Valley
на оригинальном Switch сплитскрин на двоих, а четверо — только в издании для
Switch 2.

Самый полезный источник оказался в самих данных: у многих игр число игроков прямо
названо в описании от издателя («a 2-player cooperative puzzle platformer»,
«up to 5 players per turns»). Это надёжнее любого агрегатора и не требует сети.

## Сборка

### Данные

```bash
python fetch_local_multiplayer.py
```

Собирает `local_multiplayer.json`. Кэширует карточки в `products_cache.json`,
так что повторный запуск доспрашивает только новинки. Чтобы переснять всё
с нуля, удалите кэш.

Дальше — по порядку:

```bash
python make_overrides.py     # ручные поправки числа игроков -> overrides.json
python build_db.py           # рабочая база пайплайна catalog.db
python rank_toplists.py      # рейтинг подборок -> toplists.db
python build_db.py           # повторно: подмешивает рейтинг (и переводы, если есть)
python download_art.py       # обложки в app/resources/art/
python verify_db.py          # проверки данных
python make_ship_data.py     # catalog.bin и details.bin для romfs
```

`build_db.py` запускается дважды: `rank_toplists.py` сопоставляет названия из
подборок с каталогом, а значит, каталог уже должен существовать.
`repair_catalog.py` (необязательный шаг после `fetch_local_multiplayer.py`)
добирает игры, которые перечисление Algolia пропускает, — по названиям из тех
же подборок.

На выходе `app/resources/catalog.bin`, `app/resources/details.bin` и
`app/resources/art/` (обложки 240×240, около 40 МБ).

Русские тексты об играх лежат в `translations.db` (таблица `translations`:
`nsuid, headline_ru, players_note_ru, description_ru`). Файл сделан машинным
переводом один раз и закоммичен как есть — скрипта-производителя нет. Если его
убрать, каталог соберётся с английскими текстами.

240 точек — ровно столько, сколько плитка занимает на экране в доке: окно
1920×1080 при базе 1280 даёт масштаб 1.5, и 160 логических точек плитки
превращаются в 240 физических.

### Приложение

Нужен devkitPro с `switch-curl`, `switch-mbedtls` и SDL2:

```bash
pacman -S switch-curl switch-mbedtls switch-sdl2 ninja
```

FFmpeg из pacman **не подходит**: сборка ждёт урезанный локальный
`app/lib/ffmpeg-slim`, и без него cmake останавливается. Как он собирается —
ниже, в разделе про трейлеры.

#### Видео-трейлеры

Ролики (таблица `media`, `kind='video'`, mp4/h264/aac с Cloudinary) играются
плеером собственного написания поверх FFmpeg
(`app/source/ui/video_player.cpp`): demux/decode через
avformat/avcodec, кадр конвертируется в RGBA через `swscale` и рисуется как
nanovg-текстура, звук ресемплится `swresample` и уходит в SDL2 audio.

Более привычный вариант — `libmpv`, как в NXMP и SwitchWave, — не взят:
готового пакета `switch-mpv` в pacman нет, а сборка mpv вместе с патченным
FFmpeg под `aarch64-none-elf` по рецептам
[nxmp](https://github.com/proconsule/nxmp) требует отдельного meson-тулчейна и
набора патчей. Собственный минимальный плеер поверх FFmpeg — программный
декодер, но для 30–60-секундных трейлеров этого достаточно.

FFmpeg собирается локально в `app/lib/ffmpeg-slim` (версия 7.1 — патч
devkitPro с `--enable-nvtegra` существует только для неё), из кодеков оставлены
h264 и aac. Пакет `switch-ffmpeg` из pacman здесь не используется: он тянет
полный набор кодеков и заметно прибавляет к размеру `.nro`.

Две особенности сборки, на которые легко потратить вечер:

- **Только Ninja.** Генератор Unix Makefiles ломается на пробеле в пути к
  проекту (`multiple target patterns` в файлах зависимостей).
- **`DEVKITPRO` задаётся в POSIX-виде** (`/opt/devkitpro`, не `C:/devkitPro`) и
  из PowerShell — переменные окружения из git-bash до msys2-cmake не доходят.

```powershell
$env:DEVKITPRO = "/opt/devkitpro"
cmake -B build -G Ninja -DPLATFORM_SWITCH=ON -DUSE_SDL2=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build --target SplitScreenHub.nro
```

На выходе `app/build/SplitScreenHub.nro` (~58 МБ, в основном `app/resources/art/`
в romfs). Кладётся в `/switch/` на SD-карту.

Иконка `.nro` — `app/resources/icon.jpg` (JPEG 256×256, другого формата elf2nro
не принимает). Рисуется она в `icon.svg`, а JPEG из него собирает
`python app/tools/make_icon.py`: SVG растеризует headless Chrome или Edge,
Pillow пережимает без субдискретизации цвета.

### Формат данных

В приложении нет SQLite: при трёх с половиной тысячах игр база решала задачу,
которой не существует. Сетке нужно 268 КБ на весь каталог, а любой запрос
поднимал с romfs десятки мегабайт, потому что описания лежат в тех же строках
таблицы, — время почти не зависело от числа найденных игр.

Данные лежат в двух файлах, которые собирает `make_ship_data.py`:

- `catalog.bin` (0.45 МБ) — всё, что показывает сетка. Читается целиком при
  запуске за 700 мс, дальше фильтр и сортировка считаются перебором в памяти за
  единицы миллисекунд;
- `details.bin` (5.2 МБ) — тексты и ссылки карточки, по записи на игру,
  читаются по смещению. Записи сжаты zlib с общим словарём в 64 КБ: поодиночке
  они жмутся вдвое, со словарём — почти втрое, и при этом каждая
  разворачивается отдельно.

Из зависимостей нужна zlib — она есть в portlibs devkitPro.

Отбор и порядок вынесены в `app/source/catalog_query.cpp` — без borealis и без
файлов, чтобы проверять их тестами (`app/tests/test_query.cpp`), а не запуском
на консоли.

### Рейтинг «из подборок»

Сортировка по умолчанию и фильтр «советуют» строятся на согласии источников:
19 редакционных подборок «лучшие couch co-op на Switch», 15 тредов Reddit и 3
Famiboards. Список названий из статей лежит в `toplist_sources.py`, треды и сама
формула — в `rank_toplists.py`. Коротко: вес источника — его избирательность
(`ln(P/n)`), несколько списков одного издания считаются одним мнением, редакции
и обсуждения сводятся средним геометрическим, игры с одним источником уходят в
хвост. Подробное обоснование — в докстринге скрипта.

## Проверки

```bash
python app/tools/check_xml.py   # разметка против того, что понимает borealis
python verify_db.py             # инварианты catalog.db перед упаковкой
```

Тесты чистых функций собираются обычным g++. На Windows их надо запускать из
msys2, который идёт с devkitPro, — из Git Bash компилятор не находит свои
заголовки C++, потому что там `/usr` указывает на каталог самого Git:

```bash
/c/devkitPro/msys2/usr/bin/bash -lc "cd /c/…/app && bash tools/run_tests.sh"
```

## Языки

Интерфейс и тексты об играх переключаются между английским и русским на вкладке
«Настройки». По умолчанию английский: перевода нет у части игр, и оригинал —
единственное, что можно показать наверняка. В русском режиме игры без перевода
показывают английский.

Пока язык не выбран руками, приложение смотрит на язык консоли и включает
русский только если консоль русская. Всё остальное — от французской до
японской — получает английский: русский перевод неполон, и подставлять его
вместо оригинала там, где он всё равно чужой, хуже, чем не подставлять.

Выбор хранится в `library.json` и применяется при запуске: локаль borealis
задаётся до создания окна и на ходу не меняется, поэтому переключатель просит
перезапустить приложение. Пустое поле `language` означает «как на консоли»;
как только язык выбран кнопкой, система больше не спрашивается.

Строки интерфейса лежат в `app/resources/i18n/<локаль>/hub.json`.

## Управление

| Кнопка | Действие |
|---|---|
| A | выбрать · открыть игру |
| B | назад |
| L / R | предыдущая · следующая вкладка |
| **+** | **выход из приложения, с любого экрана** |

Каталог:

| Кнопка | Действие |
|---|---|
| − | поиск по названию |
| ZL / ZR | листать сетку страницами |

Библиотека:

| Кнопка | Действие |
|---|---|
| X | на игре — убрать из списка; на папке — удалить папку |
| Y | переименовать папку |
| ZR | новая папка |

Каталог и карточка игры — кнопки одинаковые:

| Кнопка | Действие |
|---|---|
| X | положить в избранное или папку |
| Y | скрыть игру · вернуть её |

Плеер трейлера (нижней полосы подсказок там нет):

| Кнопка | Действие |
|---|---|
| A | пауза |
| Влево / Вправо | перемотка на 10 секунд |
| B | закрыть |

Кэш: X пересчитывает размер.

Подсказки для L/R и ZL/ZR намеренно убраны из нижней полосы — вместе с
остальными они переполняли её и наезжали на часы с индикаторами. Обе пары
подписаны в строке вкладок, где место есть.

Фильтры: «от N игроков», жанр, «только установленные», «есть русский», поиск и
сортировка отдельным списком справа: популярные · по алфавиту · больше
игроков · сначала новые · сначала установленные.

Избранное и папки лежат в `sdmc:/switch/splitscreen-hub/library.json`. Файл пишется
через временный и переименование, так что выдернутая посреди записи консоль не
уносит всю библиотеку.

## Известные пробелы

- **32 игры без числа игроков** — метка eShop «на одном экране» есть, числа
  нет, поэтому в каталог они не попадают. Дописываются вручную в
  `make_overrides.py` с источником по каждой; версию для Switch надо проверять
  отдельно от других платформ.
- **Оценок игр нет.** Идея — процент положительных отзывов Steam (у трети
  каталога там 50+ отзывов, ключей не нужно), с оговоркой, что это приём
  PC-версии. В интерфейс не выведено.
- **Игры, потерянные из-за меток eShop.** Часть известных couch co-op игр
  (PHOGS!, Untitled Goose Game, Unspottable) не несёт метку «на одном экране»
  при живом локальном коопе; часть не сходится по написанию названия. Каждый
  способ их вернуть меняет правила отбора, поэтому оставлено как есть.
- **Проверка сертификатов** при загрузке картинок и роликов отключена: в libnx
  нет системного хранилища корневых сертификатов, а вшитый бандл со временем
  протухает и молча ломает загрузку. Осознанный компромисс, отмечен в коде.
- **Другие регионы.** Пайплайн параметризуется одной строкой: у Algolia есть
  индексы `en_ca`, `es_mx`, `fr_ca`, `pt_br`.

Что проверяется только на консоли и вручную: расход памяти в applet-режиме,
поведение при потере фокуса и возврате из сна, сопоставление с установленными
играми через `nsListApplicationRecord`, докачка трейлеров при плохой сети.
Локально проверяются сборка, разметка и чистые функции.
